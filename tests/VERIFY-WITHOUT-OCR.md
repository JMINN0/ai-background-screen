# 不用 OCR 确认操作生效（设计，待实现）

> 2026-11-17。**这份是设计，不是实测。** 阈值的数字大多标了【推测】，必须按附录标定。

## 为什么必须换掉 OCR 验证

现在每步操作后靠 OCR 确认（1.9-3.3 秒），导致单步 1.5-3 秒。

## 核心判据不是「变没变」，是「变了之后还在不在」

### 三时点检验（最重要，实现它优先于其它一切）

| T0 | T1 = +150ms | T2 = +600ms | 结论 |
|---|---|---|---|
| 基准 | ≈T0 | ≈T0 | **什么都没发生**（点空/死区）|
| 基准 | ≠T0 | ≈T0 | **只有 ripple**（送达未生效）|
| 基准 | ≠T0 | ≠T0 | **状态改变** ✓ |

- 模板 64×64（覆盖 48dp 触摸目标），存 RAM 环形缓冲 8 份 ≈ 98KB
- 比对用 **NCC**（抗整体亮度漂移）：>0.95 同，<0.85 异

### 为什么它能修掉「BACK 108 帧 / E 64 帧」那个 bug

**帧计数是「无定位、无持久性」的全局标量 —— 108 和 64 在统计上无法区分。**

三时点检验替换了三个维度：
- **定位**：ROI 在哪
- **持久**：T2 还在不在
- **因果**：T1 有瞬态且 T2 有残留

E 键在 MC 里打开背包会让几乎整个稳定区改变并保持 → 正确判成功。
而「游戏自己在动」在 T2 时不会持续命中同一 ROI。

## 32×32 的格子几何（关键算术）

```
1592 / 32 = 49.75 px/格（横）
720  / 32 = 22.5  px/格（纵）
```

**格子是 2.21:1 的扁矩形，不是方的。** 所有 bbox、面积、半径换算必须分别用这两个数。
圆形 ripple 在格子空间里是**竖长的椭圆**。

**这条推出一个硬边界**：
- 32×32 **解析不了 ripple**（ripple 高 48-100px ≈ 2-4 格，是半透明描边）→ 必须走视频流 ROI
- 32×32 **解析得了弹窗**（26×10 格，边界清晰）→ 弹窗/键盘/翻页走 L1

## 三层分工

| 层 | 数据源 | 延迟 | 回答 |
|---|---|---|---|
| L1 结构 | 32×32 灰度 | 7.6ms | 大块结构变没变、形状、方位、持续时间 |
| L2 局部 | scrcpy 流 ROI | 29ms | 某点颜色变没变、ripple、精确边界 |
| L3 语义 | OCR | 1.9-3.3s | 变的是不是「对的东西」 |

## 七类变化分类（阈值待标定）

| 类型 | 面积 | 持续 | 决定性特征 |
|---|---|---|---|
| **ripple** | 0.4-2% | 250-500ms | **瞬时**：结束后回到 T0；单峰 |
| **页面跳转** | 55-100% | 高 MAD 2-5 帧后冻结 | **阶跃后冻结** + 结构全毁 |
| **弹窗** | 8-45% | >1000ms | **矩形 + 背景保留但整体变暗**（scrim）|
| **滚动** | 15-60% | 300-2000ms | **相干平移 + 停下后保持** |
| **键盘** | 25-40% | >1000ms | **贴底 + 水平上边界 + 内部高频** |
| **加载转圈** | 0.2-1.5% | 持续 | **周期性**（自相关峰 500-1200ms）|
| **游戏画面** | 20-80% | 永不 settle | **无周期 + 无阶跃 + 无冻结** |

### 判定顺序（必须有顺序）

```
1. A_max < 阈值              → NO_CHANGE
2. 贴底 + 上边界水平 + 高频  → KEYBOARD
3. 300ms 内冻结
   3a. 面积 > 55%            → NAVIGATION
   3b. 面积 8-55% + 背景变暗 → POPUP
4. 持续但回到 T0             → RIPPLE / SPINNER（周期区分）
5. 相干平移 + 停止后保持     → SCROLL
6. 无冻结 + 无周期 + 高面积  → AMBIENT_ONLY（放弃）
```

## 处理「画面本来就在动」

### 自适应基线

```
τ_i = max(8, 4·σ_i)     // 每格自适应阈值
```
- 静止格 σ→2 时退化为绝对值 8
- 游戏区 σ→20 时升到 80
- **先绝对后相对，不能只用 z 分数**

### CUSUM（专抓阶跃，k=1.0 是关键）

```
u_i = clip(Δ_i / τ_i, 0, 4)
S_i = max(0, 0.995·S_i + u_i - 1.0)
alarm_i ⟺ S_i > 5 且连续 3 帧
```

**k=1.0 为什么关键**：持续运动时 u≈1，增量 ≈0，随机游走不漂移 → **永不误报**。
真实阶跃 u≈4，每帧漂 3，**2 帧（15ms）就报警**。

### 稳定区域掩码（最有效）

```
quiet_i = EWMA of 1{Δ_i < τ_i},  α = 0.01
stable_mask = {i: quiet_i > 0.9}
```

游戏永远有不动的部分：血条、小地图边框、技能图标、FPS 计数。
**验证只在 stable_mask 上做**，背景运动贡献被物理扣除。

**弹窗会连稳定区一起压暗**（scrim 覆盖全屏）→ 哪怕在跑游戏也能检出。

## 送达 vs 生效（把问题拆成两维）

| 组合 | 含义 | 处理 |
|---|---|---|
| 未送达 + 无变化 | **点空了** | 高置信失败，可重试 |
| 送达 + 无变化 | **点对了但没反应** | **不是失败，别重试** |
| 送达 + 有变化 | 成功 | 正常 |
| 未送达 + 有变化 | 环境噪声 | 不算数 |

**区别就是 ripple 在不在。** 这是 ripple 值得花成本测的原因 —— 它是「输入送达」的唯一证据。

## 回退 OCR 的条件（目标 ≤10%）

```
conf < 0.6
|| class == UNKNOWN
|| stable_mask 覆盖 < 15%
|| action ∈ {付费, 发送, 删除, 授权}
|| 缓存未命中 & 首次见该屏
```

**回退率是验收指标**：>25% 说明分类器没调好，应该修分类器，不是加 OCR。

## 缓存（收益比分类器本身更大）

```
key   = dHash(8×8 网格, 64bit) ⊕ (tap 格坐标) ⊕ action_kind
value = { class, roi, ocr_text?, expected_delta, ttl }
容量   = 256 条 LRU ≈ 50KB
```

**负缓存也要存**：「这个位置是死区」同样值钱。
MC 这类重复循环命中率能到 80%+，稳态下 OCR 调用趋近于零。

## 附录：15 分钟标定协议（把【推测】变【实测】）

| # | 测什么 | 方法 | 用来定 |
|---|---|---|---|
| 1 | 传感器噪声 σ | 静止连采 1000 帧，逐格 std | ε、τ_abs |
| 2 | **空操作分布** | 空闲 30s，记 A_max 的 p99 | **有变化的判据** |
| 3 | 实际解码分辨率 | 流帧实际宽高 | 所有 px 半径 |
| 4 | 注入→首帧延迟 | 全屏闪白，测 Δ 出现时刻 | T1 起点 |
| 5 | ripple 可见性 | 连点 20 次，看 32×32 和 ROI 各自能否检出 | 确认必须走 L2 |
| 6 | 键盘几何 | 唤起前后 8×8 网格 | 贴底行数 |
| 7 | 弹窗 scrim | 弹 dialog 测亮度降幅 | 8-25% 是否成立 |
| 8 | 稳定区覆盖率 | 跑游戏 10s | 15% 下限 |
| 9 | 分类器混淆矩阵 | 用 `dumpsys window` 当真值跑 100 次 | 阈值调优 |

**第 2 项最重要**：没有空操作分布，所有阈值都还是猜的。
